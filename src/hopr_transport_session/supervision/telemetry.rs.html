1//! Bounded node-level accounting for the PIX Exit.
2//!
3//! Everything here is compiled unconditionally, including without the `telemetry` feature. Only the
4//! instruments the numbers are eventually written to live behind the feature, in
5//! `crate::telemetry::pix`. The split is deliberate: the delta arithmetic below is the part that
6//! can be wrong in a way an operator would never notice — a gauge that fails to come back down, a
7//! cycle counted twice — and a default `cargo nextest run --lib` must exercise it.
8//!
9//! # Why aggregates rather than more labels
10//!
11//! The two per-Session PIX gauges (`hopr_session_pix_gate_mode`, `hopr_session_pix_recovery_progress`)
12//! answer questions about one Session. An operator's questions are about the node: how much
13//! predeposit service is exposed right now, whether egress is blocked on deposits or on share lag,
14//! whether admission is refusing peers because the node is full or because their parameters are
15//! wrong. Answering those by adding labels would make the view worse rather than better — every
16//! `session_id`-labelled instrument stops reporting new Sessions after ~2000 of them (#8305), and
17//! nothing retires the series.
18//!
19//! So the aggregates carry no identifier at all. Every label value in this module comes from a
20//! closed enum, which is what makes that a property of the type system rather than a promise.
21//!
22//! # The census, and why it is not inc/dec
23//!
24//! [`SessionPixSupervisor`](super::supervisor::SessionPixSupervisor) recomputes
25//! [`PixSessionSnapshot`] from its own live state on every turn, and
26//! [`PixSessionTelemetry::publish`] applies the *difference* against what it last published. No
27//! transition increments a live-set gauge directly.
28//!
29//! That is what makes "gauges return to zero on every terminal path" structural instead of a matter
30//! of auditing call sites. A cycle that is retired, times out, is rolled back at admission, or
31//! disappears because its Session was dropped mid-turn is simply absent from the next census, and
32//! the delta that follows is the decrement. There is no path that can forget one, because there is
33//! no path that performs one.
34//!
35//! Cumulative *counters* are the opposite case — they must not be recomputed, because their whole
36//! value is that they survive the state they describe. Those are latched at the transition that
37//! changes the source of truth ([`PixTurnEvents`]) and drained by the same publish.
38

104/// A cycle lifecycle transition worth a cumulative count.
105///
106/// There is deliberately no `retired` event. Every `RetireSsa` follows either a tombstone expiring
107/// or [`close_ssa_and_collect`](super::supervisor::SessionPixSupervisor), both of which are already
108/// counted here, so a third event would read the same transition twice. What is left is exact:
109/// `requested = recovered + failed + (still live)`.
110#[derive(Clone, Copy, Debug, PartialEq, Eq, strum::Display)]
111#[strum(serialize_all = "snake_case")]
112pub enum PixCycleEvent {
113    /// An index was allocated and put into an `SsaRequest`.
114    Requested,
115    /// Its commitment verified.
116    Committed,
117    /// Its deposit was confirmed by the pool.
118    Funded,
119    /// It reconstructed fully.
120    Recovered,
121    /// It did not recover, whatever the reason.
122    ///
123    /// Reported for a cycle retired by the supervisor *and* for one still live when its Session
124    /// ended, which is not the same as "the supervisor named a close reason for it":
125    /// `on_unverifiable_shares` closes a Session outright without routing its siblings through
126    /// retirement, and `hopr_pix_closures_total{reason}` is where the reasons are. The label
127    /// means "did not recover".
128    Failed,
129}
130
131impl PixCycleEvent {
132    /// Whether the census accounts for this transition too, so that emitting it out of step with
133    /// the census would read the same cycle twice.
134    ///
135    /// These three are the terms of `requested = recovered + failed + live`, whose `live` term is
136    /// the census. The other two are edges the census has no opinion about: a cycle that commits or
137    /// funds moves between census buckets without entering or leaving it, so counting one twice
138    /// would be wrong but counting it out of step with the census is not. That is what
139    /// [`EventScope::EdgesOnly`] rests on.
140    fn is_census_coupled(self) -> bool {
141        matches!(self, Self::Requested | Self::Recovered | Self::Failed)
142    }
143}

170/// One episode of PIX egress being blocked, measured from first refusal until it ends.
171///
172/// # Why an episode rather than a refusal
173///
174/// A blocked gate is polled again by whatever is trying to send, so counting refusals would measure
175/// how hard the caller retries rather than how long the Exit was stalled — the issue's "a tight
176/// retry loop must not increment blocked on every failed poll". The entry into the blocked state is
177/// counted once, here, and how long it lasted is measured separately.
178///
179/// # Why `Drop`
180///
181/// The episode ends three ways, and only one of them is a return value: the gate resumes and the
182/// parked writer proceeds, the gate is poisoned and the writer fails, or the whole future is
183/// dropped because the Session was torn down underneath it. `Drop` is the one mechanism that covers
184/// all three, which is what makes "block timers close exactly once on every terminal path" hold
185/// without any of those paths having to remember.
186pub struct PixGateBlockEpisode {
187    reason: GateBlockReason,
188    began: Instant,
189}
190
191impl PixGateBlockEpisode {
192    /// Counts one episode beginning, and starts its clock.
193    pub fn begin(reason: GateBlockReason) -> Self {
194        emit_gate_block(reason.into());
195        Self {
196            reason,
197            began: Instant::now(),
198        }
199    }
200}
201
202impl Drop for PixGateBlockEpisode {
203    fn drop(&mut self) {
204        emit_gate_block_duration(self.reason, self.began.elapsed().as_secs_f64());
205    }
206}

216/// Why an incoming PIX Session was refused before it was established.
217///
218/// Bounded by construction, and finer than the wire reason it maps to. `NoSessionSlot` and
219/// `LiveCycleCapacity` are both `StartErrorReason::NoSlotsAvailable` on the wire, so
220/// `hopr_session_sent_error_count{kind}` cannot tell "this Exit is healthy but its reconstructor
221/// budget is full" from "this Exit is at its Session limit" — which are different problems with
222/// different fixes.
223#[derive(Clone, Copy, Debug, PartialEq, Eq, strum::Display)]
224#[strum(serialize_all = "snake_case")]
225pub enum PixAdmissionRejection {
226    /// The peer offered PIX to a node with no `PixToolbox` installed.
227    NoPixSupport,
228    /// The offer could not be decoded, or fell outside the accepted quota range.
229    UnacceptableParams,
230    /// The session server refused this target, or refused it on the offered terms.
231    TargetPolicy,
232    /// The node's `max_live_cycle_bytes` budget could not cover this Session's reconstructor state.
233    LiveCycleCapacity,
234    /// The node is already managing `maximum_sessions`, or this pseudonym already holds a slot.
235    NoSessionSlot,
236    /// This node could not decide right now — the session server did not answer in time, or its
237    /// request channel was full.
238    Busy,
239}

241impl PixAdmissionRejection {
242    /// Counts this refusal, if the peer was actually asking for a PIX Session.
243    ///
244    /// The capability check is here rather than at the six call sites because it is the part that
245    /// can silently be wrong: every one of those sites also refuses ordinary non-PIX Sessions, and a
246    /// `hopr_pix_admission_rejections_total` that counted those would report a PIX problem this node
247    /// does not have. `hopr_session_sent_error_count{kind}` already counts refusals of every kind —
248    /// this one exists precisely to be narrower.
249    ///
250    /// Always compiled, so the gate is exercised by the default test configuration even though the
251    /// emission behind it is not. Returns whether the refusal was counted, which is how a test
252    /// without that feature can still assert the gate rather than merely run it.
253    pub fn record_if_pix(self, capabilities: crate::Capabilities) -> bool {
254        if !capabilities.contains(crate::Capability::UsePIX) {
255            return false;
256        }
257        #[cfg(feature = "telemetry")]
258        crate::telemetry::pix::record_admission_rejection(self);
259        true
260    }

267/// One PIX Session's contribution to the node-level live-set gauges.
268///
269/// Recomputed from the supervisor's own state on every turn; see the module documentation for why
270/// it is a census rather than a set of increments.
271#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
272pub struct PixSessionSnapshot {
273    /// Which bucket of `hopr_pix_sessions_active` this Session is in.
274    pub gate_mode: PixGateMode,
275    /// Cycles requested, whose commitment has not verified yet.
276    pub awaiting_commitment: u32,
277    /// Cycles with a verified commitment, waiting for a deposit.
278    pub awaiting_deposit: u32,
279    /// Funded cycles still recovering.
280    pub recovering: u32,
281    /// Whether a recovered predecessor is still holding the paid front (0 or 1).
282    pub paid_tail: u32,
283    /// Packets this Session has been served against an unfunded front's predeposit allowance and
284    /// which no deposit has yet converted into paid service.
285    pub predeposit_exposure_packets: u64,
286    /// Whether this Session's fill has fallen back because its cycle stopped advancing (0 or 1).
287    ///
288    /// A census field rather than an edge the worker latches, so that
289    /// [`release`](PixSessionTelemetry::release) returns it like every other gauge — a Session that
290    /// dies while stalled cannot leave the count standing. [`PixStallCause::SurbStarved`] is not
291    /// here because the supervisor cannot see the SURB estimate.
292    pub stalled_share: u32,
293}
294
295impl PixSessionSnapshot {
296    /// Cycles this Session currently holds in a live (non-terminal, non-tombstone) phase.
297    pub fn live_cycles(&self) -> u32 {
298        self.awaiting_commitment
299            .saturating_add(self.awaiting_deposit)
300            .saturating_add(self.recovering)
301    }
302
303    /// The per-phase counts, in label order.
304    fn by_phase(&self) -> [(PixCyclePhase, u32); 4] {
305        [
306            (PixCyclePhase::AwaitingCommitment, self.awaiting_commitment),
307            (PixCyclePhase::AwaitingDeposit, self.awaiting_deposit),
308            (PixCyclePhase::Recovering, self.recovering),
309            (PixCyclePhase::PaidTail, self.paid_tail),
310        ]
311    }
312}

315///
316/// The supervisor is a pure state machine and cannot emit a metric, so it latches the edge and the

330    pub failed: u32,

352/// What one cycle cost and recovered, observed once when it leaves the accounting front.
353///
354/// Three histograms rather than three gauges, and observed at finalization rather than sampled,
355/// because the question is about the distribution across cycles: an Exit whose median cycle
356/// recovers fully but whose tail does not is in a different position from one where every cycle
357/// half-recovers, and an average hides which.
358#[derive(Clone, Copy, Debug, PartialEq, Eq)]
359pub struct PixCycleSummary {
360    /// How the cycle ended.
361    pub outcome: PixCycleOutcome,
362    /// Packets this Session's gate served while this cycle held the accounting front.
363    pub egress_packets: u64,
364    /// Shares accepted for it, useful or not.
365    pub accepted_shares: u64,
366    /// Of those, the ones that advanced reconstruction.
367    pub useful_shares: u64,
368    /// Useful shares that would have constituted full recovery.
369    pub target_useful_shares: u64,
370    /// What the Entry deposited for it, in µHOPR. Zero for a cycle that never funded.
371    pub deposit_uhopr: u64,
372}
373
374impl PixCycleSummary {
375    /// Accepted shares as a fraction of the cycle's payment target.
376    ///
377    /// Can exceed one, and that is meaningful rather than a defect: a conforming Entry emits
378    /// `threshold + surplus` shares per polynomial, so a fully served cycle accepts more shares than
379    /// it needed useful ones. A fraction far *below* one on a recovered cycle would be the anomaly.
380    pub fn accepted_fraction(&self) -> Option<f64> {
381        (self.target_useful_shares > 0).then(|| self.accepted_shares as f64 / self.target_useful_shares as f64)
382    }
383
384    /// Useful shares as a fraction of the payment target — how far recovery actually got.
385    ///
386    /// Exactly one for a recovered cycle by construction, which is why the histogram is labelled by
387    /// outcome: without that split the recovered population would swamp the failed one, and the
388    /// failed one is the distribution an operator wants.
389    pub fn useful_fraction(&self) -> Option<f64> {
390        (self.target_useful_shares > 0).then(|| self.useful_shares as f64 / self.target_useful_shares as f64)
391    }
392}

441/// How much of a latched batch a publish may emit.
442///
443/// The worker drains [`PixTurnEvents`] from the supervisor and *then* calls
444/// [`publish`](PixSessionTelemetry::publish), so a `release` from `close_session` — which runs on
445/// the manager's task, not the worker's — can land between the two. The batch is in the worker's
446/// hand at that point and the supervisor's latch is already empty, so whatever the publish declines
447/// to emit is gone for good. This decides what "declines to emit" means.
448#[derive(Clone, Copy, Debug, PartialEq, Eq)]
449enum EventScope {
450    /// All of it. The census is live and moves with the batch, so the two agree by construction.
451    Everything,
452    /// Only the parts nothing reads back.
453    ///
454    /// `release` has already charged this Session's outstanding cycles from its last census, so
455    /// anything that speaks about *which* cycles ended and how must be left to it or the same cycle
456    /// is accounted twice. That rules out the [census-coupled](PixCycleEvent::is_census_coupled)
457    /// counts and the per-cycle summaries, whose outcome would otherwise be free to contradict the
458    /// count that retired the cycle.
459    ///
460    /// What survives is everything that is only ever a rate: `committed` and `funded`, which are
461    /// edges between census buckets rather than entries or exits, and the share arrivals. Dropping
462    /// those would understate throughput at teardown for nothing — no gauge and no invariant reads
463    /// them, so there is no second copy for them to disagree with.
464    EdgesOnly,
465}

471/// One PIX Session's share of the node-level aggregates, and the bookkeeping that keeps it exact.
472///
473/// Created with its supervisor worker and carried on
474/// [`SessionPixSupervisorHandle`](super::worker::SessionPixSupervisorHandle), so it reaches both the
475/// worker (which publishes) and `close_session` (which releases) without a new `SessionSlot` field.
476///
477/// # Why `release` is explicit rather than only `Drop`
478///
479/// The same reason `CycleBudgetReservation` gives: a `SessionSlot` lives in a `moka` cache that
480/// drops its own clone during a later maintenance pass, and the supervisor worker is spawned
481/// detached and exits only when the last `cmd_tx` goes with it. A purely refcount-driven release
482/// would therefore zero these gauges at an unpredictable time, and until then the node would report
483/// Sessions and cycles that no longer exist. The flag is what lets both the explicit call and `Drop`
484/// run without decrementing twice.
485pub struct PixSessionTelemetry {
486    /// The gate this Session's egress passes through, read for its served split.
487    ///
488    /// Held rather than passed in, because the two callers do not both have it at the moment they
489    /// need it: `release` runs from `close_session`, which does have the gate, but `Drop` runs from
490    /// wherever the last `Arc` happens to go.
491    gate: Arc<ServiceGate>,
492    state: parking_lot::Mutex<Published>,
493    released: AtomicBool,
494}
495
496/// What this handle has already accounted for.
497#[derive(Clone, Copy, Debug, Default)]
498struct Published {
499    /// The last census, or `None` before the first publish and after a release.
500    census: Option<PixSessionSnapshot>,
501    /// The gate's `(predeposit, funded)` split as of the last flush, so the next one emits the
502    /// difference. Cumulative counters, unlike the census, are never returned on release.
503    egress: (u64, u64),
504}
505
506impl PixSessionTelemetry {
507    /// A handle that has published nothing yet, reading egress from `gate`.
508    pub fn new(gate: Arc<ServiceGate>) -> Self {
509        Self {
510            gate,
511            state: parking_lot::Mutex::new(Published::default()),
512            released: AtomicBool::new(false),
513        }
514    }
515
516    /// Publishes the difference between `snapshot` and what was last published, and drains `events`.
517    ///
518    /// The census half is a no-op once [`release`](Self::release) has run, so a worker still
519    /// draining its command channel after its Session was torn down cannot re-inflate a gauge that
520    /// has already been returned to zero. The events are a different matter: the worker took them
521    /// out of the supervisor's latch before calling this, so they exist nowhere else, and a
522    /// released handle emits what it safely can of them rather than dropping the batch on the floor.
523    /// [`EventScope`] draws that line.
524    pub fn publish(&self, snapshot: PixSessionSnapshot, events: PixTurnEvents) {
525        if self.released.load(Ordering::Acquire) {
526            record_events(events, EventScope::EdgesOnly);
527            return;
528        }
529
530        let mut state = self.state.lock();
531        // Re-checked under the lock: `release` takes it to apply its own decrements, so without this
532        // a publish that passed the check above could otherwise be applied after them.
533        if self.released.load(Ordering::Acquire) {
534            drop(state);
535            record_events(events, EventScope::EdgesOnly);
536            return;
537        }
538
539        apply_delta(state.census.as_ref(), Some(&snapshot));
540        state.census = Some(snapshot);
541        let egress = self.flush_egress(&mut state);
542        drop(state);
543
544        record_egress(egress);
545        record_events(events, EventScope::Everything);
546    }
547
548    /// Returns every gauge this Session holds to zero, and flushes its last egress. Idempotent.
549    ///
550    /// Cycles still live in the last published census are counted as
551    /// [`Failed`](PixCycleEvent::Failed), which is what keeps `requested = recovered + failed` exact
552    /// for a Session that ends with cycles in flight. `on_unverifiable_shares` does exactly that on
553    /// purpose — it closes the Session outright rather than retiring each cycle — and so does any
554    /// close that arrives from outside the supervisor.
555    ///
556    /// The egress flush is why `close_session` poisons the gate before calling this: a poisoned gate
557    /// admits nothing further, so the split read here is final rather than a moving target.
558    ///
559    /// If a publish is racing this, one census applies and the other is suppressed, and either
560    /// ordering counts each live cycle exactly once: a publish that wins first shrinks the census
561    /// this then charges, and a publish that loses leaves the older census for this to charge
562    /// instead. What the losing publish carried is not thrown away with it — it emits the part of
563    /// its batch this does not account for, which [`EventScope`] defines.
564    pub fn release(&self) {
565        if self.released.swap(true, Ordering::AcqRel) {
566            return;
567        }
568
569        let mut state = self.state.lock();
570        let last = state.census.take();
571        apply_delta(last.as_ref(), None);
572        let egress = self.flush_egress(&mut state);
573        drop(state);
574
575        record_egress(egress);
576
577        let live = last.map(|census| census.live_cycles()).unwrap_or(0);
578        if live > 0 {
579            record_events(
580                PixTurnEvents {
581                    failed: live,
582                    ..Default::default()
583                },
584                EventScope::Everything,
585            );
586        }
587    }
588
589    /// Packets admitted since the last flush, and advances the watermark.
590    ///
591    /// Returned rather than emitted so the caller can release the lock first: these are cumulative
592    /// counters, and holding this Session's lock across a global instrument would serialize every
593    /// other Session's publish behind it for no benefit.
594    fn flush_egress(&self, state: &mut Published) -> (u64, u64) {
595        let (predeposit, funded) = self.gate.served_split();
596        // `served_split`'s two loads are not atomic with respect to each other, so a predeposit
597        // permit landing between them is seen by one and not the other. Its publication order rules
598        // out the direction that would misattribute the packet; what remains is a `served_predeposit`
599        // from after the permit against a `served` from before it, which makes the *derived* funded
600        // figure come out one lower than the truth.
601        //
602        // Saturating the subtraction keeps that from wrapping a counter to 2^64. Clamping the stored
603        // watermark is what keeps it from double-counting: without the `max`, the regressed value
604        // would be stored, and every funded packet between it and the real figure would be reported
605        // a second time when the next flush crossed that ground again. The reading corrects itself
606        // on the following flush either way — this only ensures the correction is not paid for
607        // twice.
608        let delta = (
609            predeposit.saturating_sub(state.egress.0),
610            funded.saturating_sub(state.egress.1),
611        );
612        state.egress = (predeposit.max(state.egress.0), funded.max(state.egress.1));
613        delta
614    }
615
616    /// The snapshot this handle last published, for tests that assert its bookkeeping without
617    /// reading the process-wide metric registry.
618    #[cfg(test)]
619    pub fn published(&self) -> Option<PixSessionSnapshot> {
620        self.state.lock().census
621    }
622}

634/// Moves the live-set gauges from `from` to `to`, either of which may be "no Session at all".
635///
636/// Signed on purpose. A gauge is only ever nudged by the difference between two censuses, so an
637/// arithmetic slip cannot make it drift: the next publish computes its delta from the same stored
638/// snapshot and lands on the correct absolute value regardless.
639fn apply_delta(from: Option<&PixSessionSnapshot>, to: Option<&PixSessionSnapshot>) {
640    for mode in [PixGateMode::Predeposit, PixGateMode::Funded] {
641        let delta = sessions_in(to, mode) - sessions_in(from, mode);
642        if delta != 0 {
643            emit_sessions_active(mode, delta);
644        }
645    }
646
647    let before = from.copied().unwrap_or_default().by_phase();
648    let after = to.copied().unwrap_or_default().by_phase();
649    for ((phase, after), (_, before)) in after.into_iter().zip(before) {
650        let delta = i64::from(after) - i64::from(before);
651        if delta != 0 {
652            emit_cycles_active(phase, delta);
653        }
654    }
655
656    // Widened before subtracting, because both sides are `u64` and either may be the larger: a
657    // Session whose front rotates goes from a spent allowance to a restored one in a single turn.
658    let exposure = i128::from(to.map(|s| s.predeposit_exposure_packets).unwrap_or(0))
659        - i128::from(from.map(|s| s.predeposit_exposure_packets).unwrap_or(0));
660    if exposure != 0 {
661        emit_predeposit_exposure(exposure);
662    }
663
664    let stalled =
665        i64::from(to.map(|s| s.stalled_share).unwrap_or(0)) - i64::from(from.map(|s| s.stalled_share).unwrap_or(0));
666    if stalled != 0 {
667        emit_sessions_stalled(PixStallCause::ShareStarved, stalled);
668    }
669}

673    i64::from(snapshot.is_some_and(|s| s.gate_mode == mode))
674}

676fn record_events(events: PixTurnEvents, scope: EventScope) {
677    if events.is_empty() {
678        return;
679    }
680    for (event, count) in events.counts() {
681        if count > 0 && (scope == EventScope::Everything || !event.is_census_coupled()) {
682            emit_cycles_total(event, u64::from(count));
683        }
684    }
685    // Share arrivals are counted whatever the scope. Nothing reads them back — no gauge, no
686    // invariant, no other series — so a released handle dropping them would be pure loss, and this
687    // is the only copy in existence by the time it gets here.
688    for (kind, count) in events.shares() {
689        if count > 0 {
690            emit_shares_total(kind, count);
691        }
692    }
693    // Confirmed deposit value pairs with `Funded`, which is not census-coupled, so it is emitted in
694    // both scopes for the same reason that count is.
695    if events.deposit_confirmed_uhopr > 0 {
696        emit_deposits_confirmed(events.deposit_confirmed_uhopr);
697    }
698    // Phase durations are emitted whatever the scope, on the same argument as share arrivals: each
699    // states how long a phase lasted and asserts nothing about how the cycle ended, so none of them
700    // can contradict a census charge `release` has already made.
701    for (phase, millis) in events.phase_durations.iter().copied() {
702        emit_cycle_phase_duration(phase, millis as f64 / 1_000.0);
703    }
704    // The summaries are not, because each carries an outcome that must agree with the count that
705    // retired the same cycle. Under `EdgesOnly` that count came from `release`'s census charge —
706    // `failed`, uniformly — so observing a summary here could assert `recovered` for a cycle the
707    // counters have already given up on. `sum(cycle_summaries) <= recovered + failed` is documented
708    // as the expected relation precisely because a Session can end without a verdict per cycle.
709    //
710    // Recovered deposit value rides with them rather than being latched separately, so it inherits
711    // that rule from `Recovered`, which is census-coupled. The consequence is deliberate: a Session
712    // released mid-flight under-reports recovered value while still reporting confirmed, so the gap
713    // between the two counters over-states stranded value rather than hiding it.
714    if scope == EventScope::Everything {
715        let recovered_uhopr = events
716            .finalized
717            .iter()
718            .filter(|summary| summary.outcome == PixCycleOutcome::Recovered)
719            .fold(0u64, |total, summary| total.saturating_add(summary.deposit_uhopr));
720        if recovered_uhopr > 0 {
721            emit_deposits_recovered(recovered_uhopr);
722        }
723        for summary in events.finalized {
724            emit_cycle_summary(summary);
725        }
726    }
727}

892/// An in-process mirror of the aggregates, so tests can assert what was emitted.
893///
894/// Exists because the instruments themselves are behind the `telemetry` feature, which no CI job
895/// enables — a test written against them would never run. What it makes testable is the part that
896/// most needs it: whether a gauge comes back to zero. That is invisible in production until an
897/// operator compares the metric against a reality they have no access to.
898///
899/// Not a general mocking layer. It mirrors deltas exactly as the shims above pass them, so a test
900/// asserting zero here is asserting that the same sequence of calls reached the real instrument.
901#[cfg(test)]
902pub(crate) mod probe {
903    use std::{cell::RefCell, collections::BTreeMap};
904
905    thread_local! {
906        static STATE: RefCell<BTreeMap<String, i64>> = const { RefCell::new(BTreeMap::new()) };
907    }
908
909    /// Clears the probe for this thread.
910    ///
911    /// Thread-local rather than global, and that is what makes these tests independent rather than
912    /// merely serialized. Every `publish` and `release` anywhere in the crate reaches `add` through
913    /// the emission shims, so a shared map would let a test that never reads the probe still
914    /// perturb one that asserts an exact value — and `cargo test` runs tests concurrently on
915    /// threads, so a lock would have to be taken by every test rather than only the asserting ones.
916    /// A thread-local needs no discipline from either.
917    ///
918    /// The consequence to know about: a test whose emissions happen on a *different* thread — a
919    /// multi-thread tokio runtime, or a `std::thread::spawn` — will not see them here. Every probe
920    /// test drives the code directly or through a current-thread runtime, which is the same thread
921    /// throughout. A future test that needs otherwise should assert through `gather_all_metrics`
922    /// under `--features telemetry` instead.
923    pub(crate) fn reset() {
924        STATE.with_borrow_mut(|state| state.clear());
925    }
926
927    pub(crate) fn add(series: &str, delta: i64) {
928        STATE.with_borrow_mut(|state| *state.entry(series.to_string()).or_default() += delta);
929    }
930
931    pub(crate) fn get(series: &str) -> i64 {
932        STATE.with_borrow(|state| state.get(series).copied().unwrap_or_default())
933    }
934
935    /// Every series that is not currently zero, for an assertion that wants to name the offenders.
936    pub(crate) fn non_zero() -> BTreeMap<String, i64> {
937        STATE.with_borrow(|state| {
938            state
939                .iter()
940                .filter(|(_, value)| **value != 0)
941                .map(|(name, value)| (name.clone(), *value))
942                .collect()
943        })
944    }
945}

1779    /// More Sessions than the OpenTelemetry per-instrument cardinality limit, opened and closed.
1780    ///
1781    /// This is the shape that breaks the per-Session instruments (#8305): past ~2000 distinct label
1782    /// tuples the SDK folds everything further into one `otel.metric.overflow` bucket and quietly
1783    /// stops describing reality. These aggregates carry no per-Session label at all, so the property
1784    /// to prove is the other half — that the *values* stay exact over that many lifecycles, with
1785    /// every gauge back at zero and every cycle accounted for exactly once.
1786    #[test]
1787    fn two_thousand_session_lifecycles_leave_the_aggregates_exact() {
1788        const SESSIONS: usize = 2_001;
1789        const CYCLES_PER_SESSION: u32 = 3;
1790
1791        probe::reset();
1792
1793        for i in 0..SESSIONS {
1794            let telemetry = handle();
1795
1796            // Request three cycles, fund them, and let two of the three recover.
1797            telemetry.publish(
1798                PixSessionSnapshot {
1799                    gate_mode: PixGateMode::Predeposit,
1800                    awaiting_commitment: CYCLES_PER_SESSION,
1801                    predeposit_exposure_packets: 512,
1802                    ..Default::default()
1803                },
1804                PixTurnEvents {
1805                    requested: CYCLES_PER_SESSION,
1806                    ..Default::default()
1807                },
1808            );
1809            telemetry.publish(
1810                PixSessionSnapshot {
1811                    gate_mode: PixGateMode::Funded,
1812                    recovering: CYCLES_PER_SESSION,
1813                    ..Default::default()
1814                },
1815                PixTurnEvents {
1816                    committed: CYCLES_PER_SESSION,
1817                    funded: CYCLES_PER_SESSION,
1818                    ..Default::default()
1819                },
1820            );
1821            telemetry.publish(
1822                PixSessionSnapshot {
1823                    gate_mode: PixGateMode::Funded,
1824                    recovering: 1,
1825                    paid_tail: 1,
1826                    ..Default::default()
1827                },
1828                PixTurnEvents {
1829                    recovered: 2,
1830                    ..Default::default()
1831                },
1832            );
1833
1834            // Half the Sessions are closed cleanly and half die with that last cycle still live, so
1835            // both the retire-then-release and the release-charges-it paths are exercised.
1836            if i % 2 == 0 {
1837                telemetry.publish(
1838                    PixSessionSnapshot {
1839                        gate_mode: PixGateMode::Funded,
1840                        ..Default::default()
1841                    },
1842                    PixTurnEvents {
1843                        recovered: 1,
1844                        ..Default::default()
1845                    },
1846                );
1847            }
1848            telemetry.release();
1849        }
1850
1851        assert_eq!(
1852            std::collections::BTreeMap::new(),
1853            probe::non_zero()
1854                .into_iter()
1855                .filter(|(name, _)| !name.starts_with("cycles_total/"))
1856                .collect::<std::collections::BTreeMap<_, _>>(),
1857            "every live-set gauge must be back at zero after {SESSIONS} lifecycles"
1858        );
1859
1860        let requested = probe::get("cycles_total/requested");
1861        let recovered = probe::get("cycles_total/recovered");
1862        let failed = probe::get("cycles_total/failed");
1863        assert_eq!(SESSIONS as i64 * i64::from(CYCLES_PER_SESSION), requested);
1864        assert_eq!(
1865            requested,
1866            recovered + failed,
1867            "every requested cycle must end as exactly one of recovered or failed, got {recovered} recovered and \
1868             {failed} failed against {requested} requested"
1869        );
1870        assert_eq!(
1871            SESSIONS as i64 / 2,
1872            failed,
1873            "exactly the odd-numbered Sessions died with a cycle in flight"
1874        );
1875    }
