Tears down a Session slot: stops its tasks and returns what it holds.

Logs nothing at INFO, because it also cleans up a Session whose setup failed before it was established (see SessionSlotGuard). An established Session is closed with close_session.

Retires the Session’s pseudonym from the SURB store’s admitted class, but not immediately: the retire is pushed past the packet pipeline’s SURB-resolution window, so the return-routed notification a closing Exit has just enqueued — the PIX-failure notice is the one such packet — still finds its ring when the resolution stage comes to look it up. Retiring inline destroyed that ring mid-lookup, the packet was dropped, and the Entry never learned that its Session was gone (hoprnet#8515’s deposit_timeout_closes_session fails exactly there).

Deferring is only safe because the retire carries the AdmissionToken its admit returned and the store honours it only while it still names the pseudonym’s current admission. Without that guard, a retire landing in the window could invalidate a successor Session’s ring: the pseudonym is client-chosen (SessionClientConfig::pseudonym) and freely reusable, so a Session can be re-established on the same one while the previous teardown is still waiting. That failure is worse than the one being fixed — the successor would go on inserting its SURBs into the small un-admitted quarantine with nothing logged anywhere — which is why the token is load-bearing here rather than an optional nicety. Conversely, the guard means no teardown path needs its retire suppressed: a stale retire is a no-op at the store, never a lost one.

Synchronous-or-spawned, decided by the runtime: when one is running, the delayed retire is spawned on it; when none is — a Drop or the public close_session can run off-runtime — the retire happens inline. The fallback is correct because a teardown with no runtime has no packet pipeline resolving anything on its behalf either: the SURB-resolution window the deferral exists for is a property of that pipeline, so there is nothing to wait out, and retiring inline is exactly the behaviour the synchronous world had before the deferral.

Idempotent by contract, so a rollback — a Session that was never committed, hence never admitted — pays a no-op here rather than needing a separate “was it admitted?” flag threaded through the guard.
