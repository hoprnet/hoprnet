struct RetransmissionBudget {
    min_interval: Duration,
    max_services: usize,
    refill_interval: Duration,
    max_tokens: usize,
    tokens: usize,
    last_refill: Instant,
    services: HashMap<FrameId, FrameServices>,
    capacity: usize,
    throttled: u64,
}
Expand description

Peer-driven retransmission budget.

Locally-initiated retransmissions are budgeted (max_incoming_frame_retries with backoff, max_outgoing_frame_retries); the peer-driven path historically was not, so a single peer could replay a SegmentRequest naming thousands of segments and force unbounded paid egress. This bounds it with three limits, derived from AcknowledgementStateConfig: a per-frame service count, a minimum interval between two services of the same frame, and a session-wide token bucket capping how many frames can be served per refill interval.

The budget is shared by all clones of an AcknowledgementState (it lives behind an Arc in AcknowledgementStateContext), since the state is cloned per pipeline stage.

Fields§

§min_interval: Duration

Minimum interval between two services of the same frame.

§max_services: usize

Maximum number of times a single frame may be served.

§refill_interval: Duration

Interval over which the token bucket refills.

§max_tokens: usize

Maximum number of tokens the bucket can hold.

§tokens: usize

Currently available tokens; one is charged per admitted frame.

§last_refill: Instant

Last time the bucket was refilled.

§services: HashMap<FrameId, FrameServices>

Per-frame service bookkeeping. Bounded by Self::capacity: frame ids are arbitrary u32, so recording an entry per requested frame would let a bogus request grow this map without bound — entries are therefore created only for frames actually found in the ring buffer, which is itself bounded by the lookbehind window.

§capacity: usize

Hard bound on Self::services, pruned at as defence in depth.

§throttled: u64

Number of frames refused by Self::admit since the last Self::take_throttled.

fn refill(&mut self, now: Instant)

Refills the token bucket proportionally to the time elapsed since the last refill.

The bucket earns Self::max_tokens over one Self::refill_interval, so a full allowance is available again after that interval — matching what the config documents (max_frame_retransmission_burst frames served across a refill interval). Earning a single token per interval instead would make a full refill take max_tokens intervals, starving honest retry requests for tens of seconds after any burst.

Elapsed time that is not yet worth a whole token is kept, so a steady stream of calls refills at the same average rate as one call would.

Source

fn admit(&mut self, frame_id: FrameId, now: Instant) -> bool

Pure admission check for frame_id; charges one session-wide token on success.

MUST NOT create any per-frame bookkeeping: requests can name arbitrary, never-seen frame ids, and admitting them must not allocate (see Self::services). Call Self::record once the frame has actually been found in the ring buffer.

Source

fn record(&mut self, frame_id: FrameId, now: Instant)

Charges the per-frame budget for a frame that has actually been served.

Called only for frames found in the ring buffer, so this cannot be driven to grow Self::services with bogus frame ids.

Source

fn take_throttled(&mut self) -> u64

Takes the number of frames refused since the last call, for count-batched logging.
