Expand description

Supplies the expanded form of a packet key to the Sphinx sender path.

Packet keys are stored, routed and compared in their compact form, but deriving the shared secrets for an outgoing packet needs the decompressed point for every hop. That is the only place in the protocol where the expanded form is required, so it is reached through this trait rather than by widening the types that carry a path.

Expansion is CPU-intensive and a sender keeps using the same handful of relays, so implementations are free to memoize; see CachingKeyExpander in hopr-protocol-hopr.
